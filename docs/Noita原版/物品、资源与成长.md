# Noita 物品、资源与成长

> [!abstract] 先抓住这条主线
> **探索与战斗产出资源 → 拾取后进入背包、材料容器或钱包 → 通过装备组合、购物和天赋形成当局成长 → 部分发现写入跨局解锁。**

| 要理解的问题 | 原版的关键做法 |
|---|---|
| 所有资源都进背包吗？ | **物品实体、材料数量、货币余额分开记录**，拾取时才连接。 |
| 瓶子为什么能混装、泼洒和破碎？ | 物理瓶体＋按材料计数的容器＋吸取/喷洒组件；普通瓶吸取容量基准为 **1000**。 |
| 成长靠什么推进？ | 法杖和法术组合、生命上限、天赋，以及能保留下来的补给。 |
| 圣山提供什么？ | 商店、改杖区域、生命与法术补给、默认 **3 个天赋候选**。 |
| 哪些东西跨局保留？ | 进度与解锁标记；**当局取得天赋和跨局记录取得过天赋是两件事**。 |

本文分析原版的资源流转；施法过程见 [[战斗与能力组合]]，材料行为见 [[材料、地形与物理]]。数值取自本地资源，特殊模式、天赋和脚本可能覆盖初值。

## 1. 资源先分清三种存储形式

| 形式 | 记录什么 | 典型例子 |
|---|---|---|
| **实体物品** | 身份、组件、位置、父子关系和物品自身状态。 | 法杖、法术卡、瓶子、石头、掉落金块。 |
| **材料存量** | `MaterialInventoryComponent` 中每种材料的数量。 | 同一瓶中的水和血；内容物无需各自成为物品实体。 |
| **数值余额/状态** | 钱包、生命上限、效果与全局标记。 | 金钱、已取得的天赋、法术解锁。 |

例如，地面的金材料、价值 10 的金块实体、钱包中的 10 金钱，在数据上是不同对象。玩家的 `MaterialSuckerComponent` 配有吸金功能；金块则走 `gold_pickup.lua`，读取 `gold_value` 后给钱包加钱并销毁自身。两条路径最终汇入 `WalletComponent.money`。[^representation]

**地形被挖掉，不自动等于生成可堆叠方块。** 是否留下材料、生成掉落实体或更新材料库存，要看具体材料、投射物和脚本规则。现有这条资源链不能直接代表矿石冶炼、方块背包或配方合成系统。

## 2. 拾取与背包：先决定物品去了哪里，再决定它怎样工作

`ItemComponent` 描述可拾取性、自动拾取、目标背包、堆叠和使用次数；`Inventory2Component` 管理背包与当前使用物品；`ItemPickUpperComponent` 负责拾取相关行为。法杖另带施法能力，法术卡用 `ItemActionComponent.action_id` 指向法术定义。[^inventory]

一次拾取有两类结果：

- **保留实体**：法杖、瓶子等进入实体层级中的背包，切换世界中、手持和库存中的组件状态。
- **即时结算**：金块、生命心、法术刷新等执行拾取回调，修改玩家状态后销毁掉落物。

原版大量使用 `enabled_in_world`、`enabled_in_hand`、`enabled_in_inventory` 标签控制组件。瓶子落地时有物理与受伤组件，手持时有喷洒组件，内容物库存则在三个状态下都可存在。**入包改变组件的启用状态，并不只是把图标放进格子。**[^inventory]

法杖和其内部法术也有容器关系：法术实体可以作为法杖子物品，永远施放卡有不可拆卸标记。`is_stackable`、`is_consumable`、`uses_remaining` 是独立字段；不能把所有卡片的次数耗尽解释为普通消耗品被删除。背包格数、法杖容量和单个法术剩余次数也分别控制。[^inventory]

改杖权限还有区域条件。圣山创建带 `workshop` 标签的区域实体；普通出口脚本会销毁相应区域并触发坍塌。是否能够改杖还受天赋影响，具体允许移动哪类卡片由内建背包逻辑处理。[^workshop]

## 3. 材料容器：瓶体、内容物和使用动作分开处理

普通药瓶包含四组关键数据：[^container]

| 部分 | 本地配置与作用 |
|---|---|
| 瓶体 | 刚体、玻璃材质、受伤和碰撞伤害组件；能投掷，也能被破坏。 |
| 吸取 | `MaterialSuckerComponent.barrel_size=1000`，`num_cells_sucked_per_frame=5`；这是模板配置，实际吸入还受条件限制。 |
| 内容物 | `MaterialInventoryComponent` 按材料记录数量；配置 `on_death_spill=1`，破碎时可将内容物洒回世界。 |
| 使用 | `PotionComponent` 处理喷洒；瓶子同时声明可饮用物品行为。 |

瓶中装的是材料集合，因此混装后不必变成一个新的“混合药水物品 ID”。普通瓶启用 `do_reactions=20`，并允许反应产生爆炸与实体。附带文档将 20 解释为**每帧进行反应处理的 20% 概率**，不是每对材料反应成功率；单次转化量还有独立的 `reaction_speed` 参数。官方更新记录也记载过瓶内反应功能。[^container]

初始化脚本负责选择内容物并填充：普通初始装量为 1000，`EXTRA_POTION_CAPACITY_LEVEL` 可覆盖。`barrel_size` 控制吸取容量，材料库存还有独立 `max_capacity`；不能把 1000 当成所有写入路径的硬上限。初始药瓶还读取死亡次数和本地日期，所以同一种子不保证不同账户进度、日期下所有初始物品完全一致。[^initial]

粉末袋沿用“容器实体＋材料存量”的结构，但吸取组件设置 `material_type=1`，对应粉末类。它的模板容量为 1500，初始化脚本默认加入 1000 份材料；**容量和初始装量不能混为一个数字**。[^container]

## 4. 金钱：掉落、拾取、消失和消费是四步

常规 `drop_money.lua` 先计算基础掉落量，再生成对应面额金块：[^money]

`基础金额 = 10 × A × 掉落倍率`

其中最大生命内部值不大于 1 时 `A=1`，大于 1 时 `A=floor(max_hp)`；贪婪诅咒等分支还会继续修改。这里的 `max_hp` 是内部单位，不能拿界面显示的生命数字直接代入。`no_gold_drop` 标记可阻止这条掉落路径。

金币加成还可以出现在拾取阶段：`gold_pickup.lua` 根据 `EXTRA_MONEY` 效果数量逐次把金块价值翻倍。因此**掉落倍率和拾取收益倍率是两个结算点**。

普通 10 金块模板的寿命为 **900 帧**。`Gold is Forever` 对应的世界状态，会让掉落辅助函数移除金块的 `LifetimeComponent`；它改变的是掉落物能留多久。金块进钱包后，实体被销毁，不再受这个计时器影响。[^money]

技巧击杀另有 `drop_money2x.lua`，调用 `do_money_drop(2, true)`；血钱天赋会进一步改变奖励类型。**哪些伤害被判定为技巧击杀，不能只靠这两个 Lua 文件完整还原**，仍涉及内建击杀归属。

消费则由 `ItemCostComponent` 声明价格与是否可盗取，钱包记录 `money` 与 `money_spent`。商品价格文字只是显示，`shop_effect.lua` 也只产生购买特效；不能把它当成扣款实现。[^shop]

## 5. 探索与圣山：把散落收益集中转成下一阶段能力

区域场景、敌人掉落、宝箱和特殊事件提供不同来源。普通随机宝箱脚本可以给金钱、药瓶、粉末袋、法术、法杖、生命心和法术刷新，也有炸弹、伪装奖励等风险分支。开箱抽取还会优先读取 `PositionSeedComponent` 中的位置种子，不能简单推断搬动宝箱就能重新抽奖。[^reward]

圣山将多个功能放在同一过渡区域，形成明确的整备节点：

| 功能 | 原版如何提供 |
|---|---|
| 商店 | 场景标记调用 `generate_shop_item` 或 `generate_shop_wand`，创建带价格组件的商品实体。 |
| 改杖 | `workshop` 区域提供条件；出口事件可移除区域。 |
| 生命补给 | 创建圣山专用生命心，恢复生命并增加上限。 |
| 法术补给 | 刷新道具调用 `GameRegenItemActionsInPlayer`，处理有限次法术补充。 |
| 天赋选择 | 生成候选天赋及重抽装置。 |

商店按深度映射得到等级，调用者也能显式指定等级。法术价格同时考虑法术基础价格和区域等级；法杖则选择等级模板，再计算随等级增长、带随机浮动的价格。折扣另行处理。**商品等级决定候选和定价条件，并不是按玩家当前装备自动配平。**[^shop]

生命奖励尤其要分清。本地脚本在日志中用 `内部值×25` 转成显示值：[^health]

| 道具 | 拾取脚本明确修改的内容 |
|---|---|
| 普通生命上限心 | `max_hp` 增加 `1×倍率`，基准相当于显示上限 **+25**；还受上限限制。 |
| 普通全回复心 | 将 `hp` 设为 `max_hp`。 |
| 圣山全回复心 | `max_hp` 增加 **0.4**，即显示上限 **+10**，随后把 `hp` 设满。 |

普通上限心的 Lua 没有直接写当前 `hp`；上限变化后引擎怎样同步血条，要与脚本赋值区分。圣山专用心也不能直接当成普通全回复心。

另外，和平奖励检查的是 `StatsBiomeGetValue("enemies_killed")==0`，满足时在参考位置生成宝箱；离开圣山会重置这段统计。它关注的是统计计数，不等于“这一层没有任何生物死亡”，具体归属仍由引擎决定。[^pacifist]

## 6. 天赋：候选序列、选择代价和效果落点

默认 `TEMPLE_PERK_COUNT=3`。`perk_get_spawn_order` 先构造并洗牌候选序列，再根据已取得次数、可叠加限制、重复间隔和特殊排除规则处理候选；正常生成从 `TEMPLE_NEXT_PERK_INDEX` 推进，重抽另用从序列末端推进的索引。**它不是每个位置独立从完整列表等概率抽三个。**[^perk]

拾取天赋后，原版会记次数与当局标记，并通过以下方式施加能力：

- 添加长期 `GameEffect`，持续帧数设为 `-1`。
- 执行该天赋的 Lua 函数，修改组件、加入子实体或改变全局状态。
- 添加 UI 图标；标记相关效果与实体，供移除天赋时清理。

因此天赋不只改变角色数值。例如永久金块改变掉落规则，额外候选改变以后生成数量，“更多仇恨/更多爱”直接修改世界的阵营关系修正值。[^perk]

普通选择默认按 `TEMPLE_PERK_DESTROY_CHANCE=100` 清除其他候选，彩票天赋能修改这项条件。本地清理代码取的是当前 `perk` 标签实体集合，并未按圣山房间 ID 筛选；不能据此设计成彼此完全独立的房间奖励。

重抽价格为 `200×2^n`，`n` 是全局 `TEMPLE_PERK_REROLL_COUNT`。基准依次为 **200、400、800、1600……**；跨圣山共享这次游玩的重抽次数。天赋已经提供的效果、候选是否继续出现和重抽成本，是三组独立状态。[^reroll]

## 7. 当局成长与跨局解锁：记录的不是同一件事

| 范围 | 典型数据 | 含义 |
|---|---|---|
| **当局状态** | 玩家库存、钱包、生命、效果，`PERK_PICKED_*` 与拾取次数。 | 这次游玩实际拥有的资源与能力。 |
| **跨局记录** | `AddFlagPersistent` 写入的发现、击败与法术解锁标记。 | 以后可检查的进度条件。 |

天赋拾取同时设置当局 `PERK_PICKED_*`，并通常写入小写的持久取得记录。**持久记录证明曾取得，不等于下局自动获得效果**；效果仍由当局拾取流程加载。[^perk]

高阶炼金术士提供了完整例子：死亡脚本从八种希腊字母法术中抽取四张、生成钥匙，并写入 `card_unlocked_duplicate` 等持久标记；首次尚未解锁时还额外生成普通全回复心。一次事件可以同时给当局战利品和跨局进度。[^unlock]

解锁是否影响随机奖励，还要看对应生成入口。普通随机宝箱的法术生成函数会检查 `spawn_requires_flag`；首领脚本却能直接指定掉落法术。**解锁门槛属于生成规则，不能当成所有物品创建接口的统一禁令。**[^unlock]
