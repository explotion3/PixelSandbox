# Noita 敌人与世界生态

> [!abstract] 先抓住这条主线
> **区域与场景布置敌人 → 感知和阵营决定目标 → 移动能力决定接近方式 → 攻击与环境共同造成后果 → 血液、尸体、物品和事件继续改变局势。**

| 要理解的问题 | 原版的关键做法 |
|---|---|
| 敌人从哪里来？ | 地形模板中的生成标记、区域加权表，以及巢穴和事件等专用入口。 |
| 敌人只盯着玩家吗？ | 目标选择还受**检测范围、遮挡、阵营关系、攻击性和受击反应**影响。 |
| 敌人怎样适应地形？ | 地面、飞行、水中和蠕虫使用不同移动配置或专用组件。 |
| 为什么会互殴、互救或抢法杖？ | 阵营与效果影响目标；部分敌人有治疗攻击或 NPC 拾取能力。 |
| “生态”主要体现在哪？ | **生物、材料、地形、道具和奖励规则相互作用**，已知证据不等于完整种群模拟。 |

本文只分析原版已能确认的生成和行为结构。基础受伤与状态见 [[角色与环境]]，战利品和跨局解锁见 [[物品、资源与成长]]。

## 1. 区域如何布置敌人：生成点先决定机会，候选表再决定内容

常见生成链为：

`地形/场景的颜色标记 → 注册的 spawn 函数 → 条件检查 → 加权选候选 → 决定数量与偏移 → EntityLoadCameraBound`

区域脚本把小型敌人、大型敌人、独特敌人等分成不同候选表。候选可以是一种敌人、多个实体组成的队伍，也可以是空项。`min_count/max_count` 控制数量范围，`offset` 和随机偏移控制位置。[^spawn]

`prob` 是满足条件的候选之间的**相对权重**。先按 `spawn_check`、新游戏+层级、平行世界等条件筛选，再用坐标相关随机值选择。它既不是单个敌人全图出现概率，也不是每帧刷怪概率。

矿坑的小型敌人表包含弱僵尸、弱史莱姆射手、长腿怪、弱矿工和弱霰弹枪兵；大型表还有混合队伍和一次 5～10 只长腿怪的候选。**表名“大型”不保证选出来的是大体型生物，也可指更强的遭遇组合。**[^mine]

密度还有前置条件。矿坑的开放通路分支先读取区域内部纵向位置，小型生成通过阈值为 `2.1×纵向位置+0.2` 的检查后才抽表；其他通路分支不走这道检查。阈值只是该入口的门槛，不能直接当成全区域密度。[^mine]

> [!note] 同一种子仍有额外条件
> 候选可以读取日期、模式和进度。矿坑表内的圣诞矿工带日期检查；同一位置的随机取样，不等于所有日期和模式下都会生成同一批敌人。

## 2. 生成、冻结恢复和持续产怪，是三种不同过程

| 过程 | 已确认的作用 | 不应据此推断 |
|---|---|---|
| **区域生成** | 在模板或场景的生成入口决定敌人种类、数量和位置。 | 清空区域后会按原表定时补满。 |
| **相机/数量管理** | `CameraBoundComponent` 有距离、同类型数量上限及冻结恢复选项。 | 离开视野就永久删除，或重新遇到就一定是新刷出来的敌人。 |
| **巢穴/事件生成** | 具体实体或脚本在运行中继续创建敌人。 | 所有敌人共享一套持续刷怪公式。 |

附带文档明确描述：超过距离或同类型数量上限时，可以暂存实体以便恢复。实际阈值按实体配置；例如霰弹枪兵模板为 `distance=160000、max_count=30`，鱼为 `distance=2000、max_count=64`。**默认值不能替代具体模板，数量上限也不是全世界敌人总上限。**[^lifecycle]

持续产怪有独立例子：`flynest.xml` 每 **121 帧**调用一次脚本。脚本还检查随机条件、玩家是否在 **200** 距离内，以及该巢穴累计生成数是否小于 **15**；成功后才创建生物并增加计数。这是累计产出限制，不是“周围始终维持 15 只”。[^nest]

远处实体何时恢复、相同类型怎样识别、队列如何与分块加载衔接，都有内建部分；这里只确认接口与配置，不把它补写成完整刷新算法。

## 3. 一种敌人如何组成：继承基础实体，再覆盖能力与弱点

常见人形敌人沿 `base_humanoid → base_enemy_basic → 具体敌人` 继承；飞行分支使用 `base_enemy_flying`。不是每种敌人都走同一个基类，蠕虫等使用专用组件。[^templates]

| 组件/数据 | 决定什么 |
|---|---|
| `AnimalAIComponent` | 检测、攻击性、受击反应、攻击方式和部分移动决策。 |
| `PathFindingComponent` | 可走、可跳、可飞、可潜水等路径条件与搜索预算。 |
| `CharacterPlatformingComponent` | 跑动、跳跃、飞行速度，以及实际位移参数。 |
| `GenomeDataComponent` | 阵营、捕食者标记和食物链等级。 |
| `DamageModelComponent` | 生命、血液、材料伤害、燃烧与残骸等。 |
| 攻击/拾取/专用 Lua | 投射物、治疗、拾取法杖、特殊技能和死亡事件。 |

具体数值体现敌人差异。例如普通霰弹枪兵的内部生命模板为 **0.9**，弱型通过继承覆盖为 **0.36**；史莱姆射手为 **0.75**，弱型为 **0.3**，同时替换发射物。这说明难度变化可以同时发生在**模板选择、数值和攻击内容**上。[^templates]

源码还保留了生成时修改生命的入口。龙穴有未注释的 `spawn_hp_mult(...,2,...)` 调用；其辅助函数会加载指定路径的实体、修改 `hp/max_hp` 并另存派生模板。但很多其他区域的类似调用已经被注释；这些代码不能直接代表主线所有敌人的实际生命倍率，另存与加载过程还需运行核对。[^difficulty]

## 4. 感知与阵营：先发现目标，再判断它是否值得攻击

普通 `AnimalAIComponent` 暴露了以下控制：[^sense]

| 控制 | 含义 |
|---|---|
| 检测横/纵范围、角度 | 限制搜索生物的范围；不同敌人分别配置。 |
| 眼睛位置偏移 | 从这个位置发射可见性检测射线。 |
| 检测间隔 | 不必每帧重新扫描；基础人形配置最低检测间隔为 30 帧。 |
| `sense_creatures_through_walls` | 明确的穿墙感知开关，不能假设所有敌人都有。 |
| 受伤逃跑/反击、仅受击才攻击 | 改变发现目标后的反应。 |
| `mGreatestThreat / mGreatestPrey` | 记录当前认为最重要的威胁和猎物。 |

霰弹枪兵配置的横/纵检测范围为 **400/200**、角度字段为 **60**，远程攻击最大距离却是 **180**。**发现、追击和允许开火有不同条件**；看到玩家不等于马上能射击。

阵营由 `herd_id` 指向 `genome_relations.csv` 中的关系表。表按方向记录，A 对 B 可以与 B 对 A 不同，例如 `player→orcs=0`，`orcs→player=2`。这是关系值，不能直接读成攻击概率。实际反应还受攻击性、受击、魅惑和狂暴等因素影响。[^faction]

捕食关系另有 `is_predator` 和 `food_chain_rank`：文档规定等级数越大越容易被其他种类视为可捕食对象；它不是敌人的战斗等级。鱼使用 `helpless` 阵营与非捕食者配置，霰弹枪兵使用 `orcs`，史莱姆射手使用 `slimes`。

天赋还能改变全局关系：更多仇恨把 `global_genome_relations_modifier` 减 25，更多爱加 25。它们修改的是世界关系条件，不能只归入玩家攻击力。[^faction]

## 5. 移动与寻路：目标相同，也不代表走法相同

`PathFindingComponent` 配置路径是否可接受，`AnimalAIComponent` 决定行为意图，平台移动组件把意图转成位移。寻路文档还暴露搜索深度/迭代预算、搜索间隔、卡住计数和备用路径逻辑。[^path]

| 移动类型 | 原版实例与已确认配置 |
|---|---|
| 地面与跳跃 | 霰弹枪兵 `can_fly=0、can_jump=1`，另配跳跃速度、跳距、浮水和潜水许可。 |
| 飞行 | 史莱姆射手 `can_fly=1、can_walk=0`，不需要复用地面跳跃条件。 |
| 水中 | 鱼使用 `AdvancedFishAIComponent`；专用水中移动与普通人形路径不是同一套配置。 |
| 蠕虫 | `WormAIComponent` 决定游走/狩猎目标，`WormComponent` 处理分节运动等行为。 |

通道宽度也有入口：`space_required` 表示路径点需要离最近墙体多远。`path_cleanup_explosion_radius` 的文档则说明部分普通 AI 卡在地形时可清理周围；是否启用、能破坏什么，要看具体配置和内建规则。

动态地形会改变通行和遮挡条件，但**地形变动怎样使寻路缓存失效、何时重建、材料危险如何计入路径成本**，本地资料没有完整公开。现有 `path`、`next_search_frame` 和结果队列字段也不足以断定算法一定是 A*、导航网格或某种线程模型。

## 6. 攻击、治疗和拾取：行动会进入同一个世界

普通 AI 能配置近战、冲刺、远程和落地后远程攻击；`AIAttackComponent` 支持附加攻击及其距离、使用概率、持续帧、冷却和弹体。命中动画帧与允许下次攻击的时间分别记录。[^attack]

三个例子能看清关系：

- **霰弹枪兵**：攻击动作第 4 帧发射，创建 3～4 个 `buckshot` 投射物，远程攻击间隔参数为 100 帧；弹体碰撞和伤害继续由投射物组件处理。
- **治疗者**：`scavenger_heal.xml` 设置 `tries_to_ranged_attack_friends=1`，发射 `healshot`。同一套“选择目标并发射”的结构也可用于帮助友方。
- **拾杖敌人**：霰弹枪兵等带 `ItemPickUpperComponent.is_in_npc=1`，可以进入 NPC 的法杖拾取逻辑；文档还为被踢时不掉杖提供专门开关。

官方历史更新明确提过 AI 会避开某些法术，并丢弃没有可用法术的法杖。因此敌人使用地上法杖不等于无条件接受任意法术组合；完整挑选和使用算法仍在内建逻辑中。[^wand]

**敌人的攻击有实际弹体与材料后果。** 是否误伤同阵营、能否伤到施法者、遇墙如何爆炸，要继续读取投射物规则；阵营友好不能单独保证所有间接伤害安全。

## 7. 生态反馈：战斗结束后，环境不会自动归零

| 反馈 | 原版例子 | 对局势的影响 |
|---|---|---|
| 生物留下材料 | 史莱姆射手的血液为 `radioactive_liquid`，残骸材料为 `meat_slime_green`。 | 受伤和死亡能继续改变地面危险。 |
| 材料反过来伤害生物 | 不同敌人配置不同 `materials_that_damage`、燃烧和空气需求。 | 同一片液体或火焰对不同生物的作用不同。 |
| 进食影响材料 | 部分普通 AI 有 `needs_food`、`food_material`、嘴部范围和吃后粒子设置。 | 食物可以是世界材料；有字段不代表每种敌人都启用进食。 |
| 遗落装备改变威胁 | 部分敌人能拾取法杖，死亡时又受掉落配置控制。 | 同一片区域的危险会受玩家遗留物影响。 |
| 死亡影响奖励与事件 | 常规掉金、技巧奖励、首领死亡脚本、圣山和平统计。 | 同一次战斗可改变资源、进度和后续奖励条件。 |

这些反馈由材料、伤害、阵营、物品和脚本共同实现，并不要求每个生物有完整生活日程。以史莱姆射手为例：**它能飞、发射危险弹体、流出有害液体，并有与普通人形不同的材料伤害表**；战斗与环境由同一个实体配置连接。[^ecology]

对于后续融合玩法，原版中应先保留的边界是：**区域的生成身份、当前位置的真实材料、当前存活实体和当局事件状态分别存在**。把一处地形烧光或挖空，不自动等于换了区域候选表；敌人被存入远处管理，也不等于发生一次死亡。[^spawn][^lifecycle]

目前可证实的生态以局部互动和专用生成脚本为主。本篇证据尚不能支持“全世界按食物资源维持种群、繁殖、迁徙或随居民数量自动补怪”这样的完整模型。

> [!question]- 尚未确认的内部细节
> - 目标评分、记忆、放弃追击，以及受击后改变目标的完整决策顺序。
> - 阵营分值与攻击性、魅惑、狂暴等共同参与选择的精确公式。
> - 动态地形寻路的算法、分辨率、缓存失效和危险材料成本。
> - CameraBound 的类型识别、冻结序列化、恢复时机及与世界分块的衔接。
> - NPC 拾杖、法术可用性判断、误伤和技巧击杀的全部例外。
